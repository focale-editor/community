# Contributing to Focale Community

You can help by reporting bugs, describing a missing capability, suggesting a
better workflow, answering questions or checking whether a fix works for you.
English and French are both welcome.

## Bug reports

Search existing issues, then use the [bug report form](https://github.com/focale-editor/community/issues/new?template=01-bug-report.yml).
Describe a short sequence someone else can follow, the result you expected and
what actually happened. If a crash is intermittent, include the last actions you
remember and how often it happens; a perfect reproduction is not required.

Include the Focale version and build number, operating system and version, and
relevant hardware. For website problems, give the page URL and browser version.
For installation or update problems, include the package filename or download
URL and the installed and offered versions.

For image or format problems, a small sample and the format, dimensions, color
mode and bit depth are useful. For slow operations, describe the document size,
layer count, hardware and approximate duration. Only share files you are allowed
to make public. Redact personal information from screenshots and logs.

## Features and improvements

Explain the task you want to complete, where the current workflow falls short
and what a good result would look like. Mockups and comparisons can help, but
describe the need in your own words. Include a workaround if you have one.

Use **Feature request** for a new capability and **Improvement** to refine
something that already exists, including accessibility, performance, wording
and documentation. One idea per issue makes discussion and follow-up easier.

## Questions and existing issues

Check the [documentation](https://focale-editor.app/docs) first. When asking a
question, explain what you want to do and what you have already tried.
Use a reaction to support an existing proposal. Comment when you have new
information, a reproduction or another workflow that helps explain the need.

Be respectful, discuss the work and assume good intent. Maintainers may moderate
spam, harassment and disclosure of private information.

## Pull requests

Keep changes to this repository focused on its documentation and issue forms.
Describe what changes for contributors and link any related issue. Application
feature requests belong in issues; changes to an open-source library belong in
that library's repository.

For Markdown, verify relative links and run `git diff --check`. For forms, check
the [GitHub form syntax](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms)
and keep template filenames consistent with the direct links in the README.
After publication, check the issue chooser and required fields on GitHub.
